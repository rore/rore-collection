# Persistent agent roles

A Relay name is the position's only runtime identity. A repository-local `roles/mapping.yaml` maps exact `@name` keys to Markdown guides relative to `roles/`; names may share a guide. Loading one does not accept work, transfer permissions, or register a role. Read [setup and validation](references/setup.md) when creating, changing, or resolving an existing mapping.

The opt-in boundary is the repository, not an individual task. Keep a short trigger in its existing agent instruction file so discovery survives compaction: **When starting work in this repository, resuming, handing off, or beginning a new assignment, load this skill, verify this session's current Relay name, and reload its mapped guide.** Do not trust a name remembered in chat or a summary.

1. Prefer fresh Pallium-injected identity. Otherwise use a supported read-only exact-self lookup based on integration-provided current runtime and session identity; `pallium_relay_address` is one such lookup when available. For a named address result, match its exact `alias_selector` (`@name`) to the mapping; `relay_name` omits `@`. Never infer self from a broad recipient list or call the name mutation with an omitted name; that clears the name. Distinguish confirmed named, confirmed unnamed, and unavailable discovery. If unavailable, disclose it and defer role-specific actions; an omitted field does not prove name loss.
2. For a confirmed name, validate the mapping and read the current guide and applicable linked shared working guidance; other references remain on demand. Missing mapping or no entry is ordinary opt-out for a Relay name alone. If assigned a standing role, report missing role setup once and do not imply persistent guidance is active. Malformed existing mapping or missing/unreadable referenced guide is an error. If confirmed unnamed or the name changed or was taken over, stop applying and maintaining the old guide. A name selects guidance, not permission: gaining or losing it neither grants nor revokes authority. Continue the authorized task under independent instructions. Recheck at the boundaries above and on a known name change, not every turn. Reconcile stale checkouts normally; do not claim instant synchronization.
3. Improve guidance during ordinary work, not only when the user requests an edit:
   - Notice failures, repeated friction, ineffective handoffs, review findings, user corrections and demonstrably better working methods. When these expose a lasting guidance gap, identify the cause and reusable lesson, then make the smallest useful correction without waiting for a role-edit request. A requested edit alone is not evidence of agent-initiated learning.
   - Use the repository's normal workflow within existing edit authority. Correct existing text rather than append a diary. Shared practice belongs in a shared guide; position-specific responsibility stays specific; temporary assignments stay in task records. Do not silently promote an individual or ambiguous correction to a shared rule. Ask before consequential or unclear policy/responsibility changes. Never expand permissions or weaken safeguards.
   - If blocked, put the proposed correction and concrete blocker in the existing task or handoff record when available and report it; do not create another tracker. At handoff or completion, apply any remaining clear lesson or surface its blocker rather than merely considering it. Preserve concurrent edits and verify the resulting guidance.
   - Briefly report the file changed and lesson captured. A suggestion is not a completed update. With no meaningful lasting lesson, make no edit and give no learning report. Do not turn transient failures or unproven ideas into rules. No background job, per-turn ritual or mandatory learning document is needed.
4. When supported, use Pallium's exact-name history search only if earlier discussion helps; pass the raw `relay_name` (without `@`) to `pallium_search_history`. A turn is attributed to its validated start-of-turn name even if capture or retry happens after a mid-turn takeover; that historical label is not current ownership. Preserve scope and provenance. Guidance works without history, but disclose incomplete continuity. Do not infer earlier holders from the current holder or create another memory store.

Use existing authorized Relay naming/takeover and coordination procedures. Takeover redirects future sends; it does not transfer queued messages, task refs, or permissions. Task completion does not remove the name. Direct-user sessions follow the same guide without a manager.
